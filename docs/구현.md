# 구현 정리

기획은 [기획서.md](기획서.md), 그림 규칙은 [아트디렉션.md](아트디렉션.md)에 있다. 이 문서는 **코드가 어떻게 짜여 있고, 무엇을 어디에 추가하는가**를 다룬다.

## 한눈에

```
화면 흐름   Boot ──► Title ──► Field ⇄ UI(겹침)
                      ▲          │
                      └──────────┘  챕터 끝 / 타이틀로
                     Field/Area ──► Action(싸움, 탑뷰 액션) ──► Area / Field
```

- **Field**: 탑다운으로 걸어 다니는 곳. 한 번에 한 페이즈(어디서·누가·무슨 일이)를 돌린다.
- **UI**: Field 위에 겹쳐 도는 씬. 대화창·말풍선·HUD. 카메라 배율과 무관하게 글자가 선명하다.
- **Action**: 모든 싸움. 길 위의 무리와 부딪히거나, 습격·대본(시험·결투)·보스에서 넘어가는 탑뷰 실시간 액션(세피리아·하데스 계열). 동료는 없다 — 주인공 혼자 싸운다.

## 핵심 규칙: 지워짐 (`src/core/world/WorldMemory.js`)

- **CONTINUE = 로드**. 누적 로드 +1. 네다섯 번에 한 번(4·9·13·18번째 로드, `ERASE_GAPS`) 한 명이 지워진다. 1부는 마을 사람(`ERASE_ORDER`), `part1.done` 뒤로는 히로인(`HEROINE_ORDER`)도.
- 누가 지워지나: 지워질 수 있는 사람(`erasable: true`) 중 **호감도가 가장 높은 사람**. 동점이면 `ERASE_ORDER` 순서.
- **RESET & START**는 진행(run)만 처음으로 돌린다. 세계(world)의 지워짐과 로드 횟수는 남는다.
- 지워진 사람은 필드에 배치되지 않고, 그 자리에 `remnant`(흔적 소품)가 남는다. 대본은 `unlessErased` / `ifErased` 조건으로 갈린다.

## 페이즈와 이벤트 (`content/chapters/*/phases.js`)

선택창은 없다. 갈림길은 플레이어의 행동이 만든다.

```js
{ id: 'hort.spill', when: { unlessErased: 'hort' }, trigger: { near: 'hort', r: 4 }, run: 'festival.hort_spill' }
```

| trigger | 뜻 |
| --- | --- |
| `{ near, r }` | 인물/장소 근처에 가면 (r: 타일) |
| `{ zone }` | 구역에 들어서면 (`maps/village.js`의 zones) |
| `{ timer }` | 페이즈 시작 후 n초 |
| `{ afterFlag, delay }` | 플래그가 켜지고 n초 뒤 |
| `{ dwell, r, seconds, ticks }` | 그 곁에 누적 n초 머물면. ticks로 도중 말풍선 |
| `{ idle, near, r, minTime }` | 그 곁에서 가만히 n초 |
| `{ pickedAll, near?, r? }` | 흩어진 물건을 다 주웠으면 (+그 사람에게 가면) |
| `{ count: [플래그…], n }` | 플래그 n개 이상 |
| `running: true` (다른 계기에 덧붙임) | 뛰어서 지나갈 때만. 같은 방향키를 빠르게 두 번 누르면 달린다(`RUN_SPEED`·`RUN_TAP`) |

- 이벤트는 한 번만 실행되고 `done.<id>` 플래그로 기억된다(이어하기 후에도 반복되지 않음).
- `when`은 대본 조건과 같은 문법이다(아래).
- 인물 배치에도 `when`을 달 수 있다(예: 셀레나와 이야기한 뒤에만 루가 있음).
- E 키로 말을 걸면 `talk.<페이즈>.<인물>` 컷신이 있으면 처음 한 번 실행, 이후엔 말 걸기 대화(`content/talk/talk.js`, 2~4장·길 위의 마을은 `content/talk/roads.js`). 인물·페이즈 이름 오타는 `tests/unit/talk.test.js`가 잡는다.

## 컷신 대본 (`content/chapters/*/script.js`)

```js
'festival.hort_thanks': [
  T('hort', '오, 다 주워왔냐!'),
  T('tom', '어라. 이 얘기 아까도 하지 않았나?', { minLoads: 1 }),
  { aff: { hort: 2 }, flag: 'ev.hort' },
],
```

| 노드 | 뜻 |
| --- | --- |
| `N(문장)` / `T(인물, 문장)` | 내레이션 / 대사 |
| `T(인물, 문장, { face: '표정' })` | 그 표정의 일러스트로 말한다(`content/cg.js`의 `PORTRAITS.<인물>.faces`) |
| `B(인물, 문장)` | 말풍선 (대화창 없이) |
| `WALK` (라벨 첫 줄) | 걸으며 듣는 대사. 아래 참고 |
| `{ fx }` | `shake` `bell` `flash` `fade` `glitch` |
| `{ cg: 'id', tint? }` / `{ cg: null }` | 이벤트 CG 띄우기 / 내리기(`content/cg.js`). 컷신이 끝나면 저절로 내려간다. 걷는 대사 중에는 띄우지 않는다 |
| `{ aff: { 인물: n } }` | 호감도 |
| `{ flag }` | 플래그 켜기 (aff와 한 노드에 같이 써도 된다) |
| `{ act: 'spawnPickups', group, prop, items, expire? }` | 물건 흩뿌리기 |
| `{ act: 'spawnNpc', id, at \| near:'player', offset }` | 인물 등장 |
| `{ act: 'walkTo', id, path: [[x, y], …], wait? }` | 경유지를 차례로 걸어가 그 자리에 머문다(사라지지 않음). 경유지가 막힌 칸이면 검증에서 잡는다 |
| `{ act: 'walkAway', id, to }` / `{ act: 'despawn', id }` | 퇴장 |
| `{ ask: 'id', options: [2~4개] }` | 바깥을 향한 질문 — 이 게임에서 유일한 선택지(`ui/ChoiceBox.js`). 고른 답은 `ask.<id>`·`ask.<id>.<번호>` 플래그로 남는다. 걷는 대사엔 둘 수 없다 |
| `{ act: 'battle', enemies, note?, winLine?, flag? }` | 그 자리에서 싸움(탑뷰 액션, `systems/FieldBattle.js`). 혼자 싸운다. 이기면 flag. 지고 물러나면 그대로 다음 노드로(뒤 노드는 ifFlag로 갈린다) |
| `{ phase }` | 같은 장의 다음 페이즈로 |
| `{ end: 'title', next: { chapter, phase } }` | 타이틀로, 다음 이어하기 지점 지정 |

조건(모든 노드): `ifErased` `unlessErased` `ifErasedAny` `minLoads` `maxLoads` `ifFlag` `unlessFlag`(이름 하나 또는 목록) `afterTime`·`beforeTime`('HH:MM') `minDay`·`maxDay` `ifQuest`('id' / 'id.done' / 'id.step2') `anyOf: [조건…]`(하나라도 맞으면) `maxForestChops`·`minForestChops`(깊은 숲에서 벤 나무 수)
문장 안 치환: `{bells}`(13 + 로드 횟수), `{loads}`, `{lastErased}`(가장 최근에 지워진 사람 이름)

### 대사의 두 방식

| | block (기본) | walk (`WALK`) |
| --- | --- | --- |
| 플레이어 | 멈춘다 | 계속 걷는다 (물건도 주울 수 있다) |
| 표시 | 아래 대화창 + 작은 도트 얼굴 | 화자 머리 위 말풍선, 내레이션은 허공에 떠오르는 글 |
| 넘기기 | 키를 눌러야 | 저절로 (Space로 빨리) |
| 놓침 | 없음 | 화자에게서 6칸 넘게 멀면 `…`만 흐릿하게, `missed.<라벨>` 플래그 |
| 쓰는 곳 | 에다·종소리·미아의 '에다?'·셀레나·루·정리자·종탑 | 나머지 전부, 모든 `talk.*`, 배경 주민끼리의 엿듣는 대화 |

페이즈 전환·장 끝은 block 장면에서만 일어난다(테스트가 지킨다).

### 지워진 이름

마을 사람 입에서 지워진 사람의 이름은 특수 문자로 깨져 흐리게 떨린다(`!@#$` 같은 꼴, 글자 수는 그대로, 같은 이름은 늘 같은 모양). 가 본 적 없는 마을의 이정표도 같은 식으로 깨진다. 내레이션과 주인공은 온전히 말한다. 지워진 사람 = 로드로 지워진 사람 + 대본상 사라진 사람(`gone: { notInPhases }`, 에다는 수확제 밤에만 있다). 대본에 이름을 그냥 쓰면 엔진이 알아서 깬다.

### 빈자리 찾기 (1장)

지워진 사람의 흔적을 E로 살펴보면 `found.<id>`, 목표 옆에 `빈자리 n/m`. 다 찾으면 `found.all` → 종탑에서 한 줄이 더 보인다. 강제는 아니다.

## 사람과 부딪히기 (`src/field/systems/Crowd.js`)

- 사람은 몸이 있어 부딪히지만 길을 막아 세우지는 않는다. 서 있는 사람에 부딪히면 그 사람에게서 먼 쪽으로 비껴 돌고, 같은 사람을 0.35초(`PASS_AFTER`) 넘게 밀면 비켜 준 듯 지나간다(좁은 문 앞·골목). 몸이 떨어지면 다시 막는다.
- 길을 가는 사람(일과·컷신 이동)과 따라오는 사람은 막지 않는다. 걸어가던 사람이 나를 덮쳐도 갇히지 않는다(이미 겹친 사람은 막지 않는다).
- E는 사람이 먼저다: 곁에 사람이 있으면 동물·물건은 그 사람보다 훨씬(`PERSON_FIRST`, 0.6배) 가까워야 E를 가져간다. 사람 앞에서 지나가던 고양이를 쓰다듬지 않게.

## 건물 이름 명패와 가게 진열 (`src/field/systems/Signs.js`, `src/ui/SignPlate.js`)

- 이름 있는 건물(맵 objects의 `name`) 문 앞에 다가가면 문 위에 흰 명패로 이름이 뜬다(호르트네 빵집, 에다의 대장간, 리네의 꽃집, 기사단 초소, 종탑…).
- 그 집 사람(`owner`, 없으면 `residents`의 첫 사람)이 지워졌으면 세상은 이름을 모른다: `nameGone`(빈 가게, 빈 대장간…) 또는 '빈집'.
- 가게 앞 진열은 팩의 TilesetHouse 그림: 빵 상자(`crate_bread`·`crate_loaves`), 채소·생선·사과 바구니, 밀가루 자루, 화분.

## 건물 안 (`content/maps/myhome.js`)

- 마을 맵의 `doors: [{ at, room }]`: 문 앞 칸에서 위로 몸을 들이밀면 그 방으로 들어간다(키를 따로 누르지 않는다). 방의 `exits`에 `back: true`인 출구로 나오면 문 앞.
- 방은 같은 페이즈·같은 시각을 이어 간다. 사람·이벤트는 바깥에 두고, 방의 `life`(생활 자리)·`props`(소품)·`lights`만 쓴다.
- 우리 집: 침대(밤엔 잠 → 다음 날, 낮엔 낮잠으로 피로), 식탁(집밥), 책장·서랍장·화분·깔개(팩의 TilesetElement 가구, 깔개는 `flat`이라 늘 사람 아래). 침대는 이 리포의 팩에 없어 팩 색으로 찍었다(`tools/build-assets.mjs`의 buildFurniture). 받은 물건(리네의 화관, 호르트의 바구니, 페르의 류트). 준 사람이 지워지면 먼지 자국(`dust`)만 남는다.
- 화면보다 작은 맵은 카메라가 가운데에 둔다.
- 페이즈의 `props`에 `run`(대본 라벨)을 달면, 그 소품을 살펴본 뒤 그 장면이 한 번 이어진다(`looked.<라벨>`). 프롤로그 아침의 모루.

## 여러 마을 (이야기 필드의 맵)

- 페이즈의 `map`(기본 `'village'`)이 그 페이즈의 맵이다(`content/maps/index.js`의 `MAPS`). 맵 모듈은 같은 꼴을 따른다: `id` `W` `H` `FOG` `terrain` `objects` `solids` `exits` `entry(dir)` `isSolidPx` `isSolidTile` `spots` `zones`.
- 다른 마을에 들르기: 전체 지도의 거점에 `field: '<맵 id>'`가 있으면, 길 맵에서 그 칸에 들어설 때 지금 장의 `visit: true` 페이즈(조건 `when`이 맞는 것)로 들어간다(`src/world/visits.js`). 없으면 길 맵의 빈 거점 그대로다.
- 들르는 페이즈는 `keepTime: true`로 시계를 이어 간다. 고향에서 길로 나갈 때 돌아올 페이즈가 세이브 v8의 `run.home`에 남는다(다른 마을에서 이어하기를 해도 고향으로 돌아갈 수 있다).
- 인물 파일의 `home`(사는 맵, 기본 `'village'`): 그 맵에 있을 때만 하루 일과를 산다. `away`(조건): 그 조건인 동안은 마을에 없다.
- 장의 고향 페이즈에 `onRoad: true`면 이야기가 길 위의 마을(visit 페이즈)에서 이어진다(2부 4장).
- 1장부터 들를 수 있는 마을: 빈 마을(사람 없이 문패와 이름 벽만), 서리 마을(사나운 마을. 해 질 녘마다 오크가 내려오고, 브렌나와 둘이서 막는다), 항구(마를로·넬), 드워프 마을(브로크·헬가). `content/places/`에 두고 장마다 섞는다.
- 항구의 남쪽 끝(선착장)과 드워프 마을의 북쪽 끝(갱도)은 길 맵의 그 거점 칸으로 이어진다. 배와 계단은 길 맵에 있다.
- 엘프 마을(엘프 파수꾼·장로 실웬): 깊은 숲을 한 그루도 안 벴으면 엘프가 보이고(`maxForestChops: 0`), 조금 벴으면 마을은 있지만 사람이 숨고, 지나치게 벴으면(`ELF_FOREST_LIMIT`) 마을로 들어가지 않고 길 맵의 그루터기 숲이 된다(`src/world/visits.js`의 문턱).
- 빈 마을은 건물·나무 색을 바랜다(맵의 `objectTint`).
- 도시 둘(`content/places/trade.js`·`magic.js`, 사람은 `content/characters/folk.js` 한 파일): 로웬(surface:9,13, 분수 광장의 교역 도시 — 장터 천막·상인 조합·여관·경비대), 아스테라(surface:1,8, 엘프 마을 너머 깊은 숲의 마법 도시 — 마법사의 탑·마력 수정·대서고. 숲을 지나치게 베면 엘프 마을처럼 길이 열리지 않는다). 분수와 마법사의 탑은 팩에 없어 팩 색으로 찍었다(`tools/build-assets.mjs`의 buildFountain·buildMageTower), 장터 천막과 사자 머리 분수는 TilesetDesert, 수정은 TilesetTowers.
- 우리 마을 사람은 가족 단위로 산다(이야기 인물 포함 서른일곱): 오토네(베르타·릴리, 철마다 오는 일꾼 야코프·마그다), 목수 한스네(엘사·핀, 은퇴한 아버지 고트프리트), 사냥꾼 이반과 카이, 마르타 할머니와 테오, 잡화점 그레타·볼프와 딸 레니, 세탁부 로사와 엘라, 견습 동기 브람·소냐, 미아네(엄마 안나·아빠 게르트), 빵집 견습 한나와 배달하는 닐스, 종지기 울리히, 경비병 프리츠. 집 문(`residents`)으로 드나들며 하루 일과를 산다.
- 다른 마을의 배경 주민은 `content/characters/residents.js` 한 파일(`RESIDENTS`): 항구(항구지기 하랄, 선원 얀·스벤, 마를로의 아내 오다와 손자 핌 — 얀은 엘라의 아빠다), 서리 마을(사냥꾼 비요른·잉그리드 부부, 여관 일꾼 토베, 망루 경비 아스케), 드워프 마을(광부 구르니·발드라, 견습 대장장이 코림, 맹세의 전당 지기 햘마), 옆 마을(견습 무녀 미레이, 빌마·에곤 부부와 아들 틸로), 영주의 성 아랫마을(병사 콘라트, 여관 주인 그리어, 상인의 딸 페나), 물레방아 마을(빗자루 신도 로테, 일꾼 루프레히트), 기록하는 마을(아가테와 아들 루디, 노인 로렌츠). 대화는 `lines`에 두고, talk.js가 `'*'`(그 사람이 서 있는 어느 페이즈에서나)로 합친다. 대화 하나를 `(ctx) => 줄 | null`로 쓰면 그때의 상태(플래그·지워진 사람)를 보고 고르거나 건너뛴다.
- 습격은 그 습격의 `map`(기본 우리 마을)에만 온다. `daily: true`면 날마다 그 시각에.

## 마을 밖으로 (전체 지도와 길 맵)

- 전체 지도는 `content/world/world.js`. 칸 하나 = 맵 하나, 거점 사이는 4~6칸.
- 마을(이야기 필드)의 출구는 `village.exits`. 페이즈가 `exits: ['n']`처럼 열어줄 때만 안개가 걷히고 지나갈 수 있다. 지금은 1장부터 북쪽 길이 열린다.
- 출구 끝을 밟으면 `Area` 씬이 그 칸의 맵을 `buildArea(layer, at)`로 만들어 띄운다. 맵 끝 출구를 밟으면 이웃 칸으로, 시작 마을 칸으로 돌아가면 `Field`로 돌아간다(들어온 쪽 출구 자리에 선다).
- 바닥은 기후 테마(`pack.js THEMES`: 마을·풀·눈·모래·마른 땅)로 그린다. 바닥 시트의 블록이 같은 배치로 반복돼서 흙길 자동 타일 좌표를 옮기기만 하면 눈길·모랫길이 된다.
- 처음 간 칸은 `visited.<칸>` 플래그가 켜지고 그곳 설명이 허공에 떠오른다.
- 길 맵마다 살펴볼 거리가 하나씩 있다(E). 거점 옆 칸은 이정표(가 본 적 없는 마을 이름은 깨져 있다), 곁가지 구역은 그 지형지물(`found.side.<칸>`), 나머지 길은 기후별 흔적 글(`content/world/features.js`, `{loads}` 치환).
- 층 사이 계단: 드워프 마을 ↔ 갱도 입구, 고대 유적 ↔ 유적 아래 회랑. 계단을 밟으면 넘어간다. 지하와 은하는 늘 밤처럼 어둡다.
- 은하: 종 걸린 절벽의 종을 열세 번. 실제 밤(20시~4시)이고 `found.all`이어야 열린다(`ringBell`). 은하 쪽엔 돌아가는 계단.
- 땅 색 테마: 갱도(어두운 흙), 용암(달궈진 땅), 은하(보랏빛) — 바닥 위에 곱하기로 색을 덮는다.
- 바닷길: 항구 남쪽은 물가, 선착장 끝의 배에서 E → 바다 칸으로. 바다에선 배를 타고 다니고(물 위 어디든, 바위만 막힘), 항구 쪽 출구로 돌아오면 배 옆에 내린다. 바다 유적은 실제 시각의 조수(12시간 25분 주기 중 3.1시간 썰물, `lowTide`)에 따라 썰물이면 지붕이 섬처럼 드러난다.
- 떠돌이: 길 맵에 칸·날짜로 정해진 사람이 가끔 있다(같은 날 같은 칸이면 같은 사람). 나그네는 추운 길, 상인은 따뜻한 길, 정신체는 어디서든. E로 말을 걸면 말풍선으로 한 줄씩. 정신체는 가장 가까운 '아직 안 간 곁가지' 방향을 알려주고(`spiritHint`), 마을 사람과 달리 지워진 이름을 온전히 말한다.
- 길 맵 안 저장: 세이브 v3의 `run.where`. 길 맵에 들어가면 그 칸이 저장되고, 마을로 돌아오면 비워진다. 이어하기(로드 대가는 그대로)는 그 칸 가운데서 시작한다.
- 몬스터: 길 맵에 칸·날짜로 정해진 무리가 보이고, 부딪히면 전투. 이기면 `beat.<칸>.<날짜>`(보스는 `beat.boss.<칸>`, 영구).
- 보스 자리(`content/battles/encounters.js`의 `BOSSES`): `when`(나타나는 조건), `party`(같이 싸우는 사람), `flag`(이기면 켜짐). 2장의 길 잃은 기사는 `surface:5,10`(옆 마을 가는 안개 길)에서 나·루 둘이서.

## 싸움: 탑뷰 액션 (`src/action/engine.js`, `src/scenes/battle/ActionScene.js`, `content/action/`)

이 게임의 모든 싸움이다(길 위의 무리, 마을 습격, 시험·결투, 보스). 사이드뷰 턴제는 뺐다. 손맛은 세피리아·하데스 계열: 바닥의 붉은 예고를 읽고 피하고, 틈에 벤다.

- **동료는 없다.** 주인공 혼자 싸운다. 나중에 싸우지 못하는 히로인을 데리고 다니며 지키는 경우가 생길 수 있다(장비는 입힐 수 있다). 아직 없다.
- 조작: 방향키 이동 · 마우스 조준·클릭 기본 공격(누르고 있으면 계속) · 스킬 Q W E R(찌르기·휘두르기·막기·돌진, `CONTROLS`에서 바꾼다) · 1~8 퀵슬롯.
- 적(`content/action/foes.js`, 보스 빼고 스물다섯 가지 남짓): 들판의 슬라임·큰 슬라임(쓰러지면 둘로 갈라진다, `split`)·독 슬라임·들개·우두머리 들개·불짐승·잿빛 짐승, 숲의 올빼미·밤 올빼미, 눈밭의 서리 슬라임·눈 올빼미·얼음 두더지, 굴의 두더지·바위 두더지, 해골·재 해골·해골 기사·해골 주술사, 화산의 불씨 슬라임, 습격의 오크·오크 사냥꾼·오크 장정, 2부의 악마·큰 악마, 그리고 보스(토르크·레온·길 잃은 기사·정리자의 그림자). 팩의 몬스터 그림이 다섯 가지뿐이라 색(`tint`)·덩치(`scale`)·버릇을 바꾼 갈래로 늘렸다(전리품은 `base`의 것). 팩 전체판의 몬스터 그림이 들어오면 `art`만 바꾼다.
- 적의 공격은 다섯 꼴: 부채꼴 `sweep`, 직선 돌진 `lunge`, 조준 탄 `shot`, 둥근 탄 `ring`, 쫓아오는 탄 `motes`. 모두 먼저 바닥에 붉게 예고한다(`tell`초). 원거리 적은 거리를 지키며 옆으로 돈다(`keep`). 보스는 정해진 순서로 쓰고, 체력이 `enrageAt` 아래면 빨라진다.
- 무리(`content/battles/encounters.js`의 `POOLS`): 기후마다 8~14마리. 한 번에 여섯(`MAX_ALIVE`)까지 나오고, 쓰러지면 남은 무리가 가장자리에서 들어온다. 화면 위에 '남은 적'.
- 몸이 싸움을 바꾼다(`bodyMods`): 생활 상태의 체형·마음가짐·피로·히든 스킬 → 체력·피해·이동·돌진 재사용·상태이상 저항. 통통하면 오래 버티고, 마른 몸은 빠르고 돌진이 자주 돈다.
- 막기(E): 앞쪽 공격을 줄인다. 막 시작했을 때(완벽한 막기)는 완전히 막고 그 적을 기절시킨다. 거울 방패면 탄도 막고 되받아친다.
- 회복: 붕대·약초는 맞지 않는 동안만 차고 맞으면 끊긴다. 물약만 즉시(귀함). 처음 싸울 때 기본 소모품을 한 번 준다(`STARTER_KIT`).
- 상태이상 8종: 화상·중독(겹침, 회복 막음)·출혈(움직이면 2배)·둔화·기절·빙결(다음 피해 1.5배)·약화·취약.
- 지면: 되돌리기(R) = 로드(네다섯 번에 한 번 누군가 지워진다), 같은 싸움을 다른 씨앗으로 다시. 물러나기(Esc)는 길 맵으로(습격이면 놈들은 그대로 간다).
- 이기면: 그날 그 칸의 무리는 없다(`beat.<칸>.<날짜>`, 보스는 영구). 무리마다 그럴 만한 것을 떨군다(`DROPS`, `rollDrops`). 보스는 처음 이길 때 장비(`drops`: 정리자 → 쌍날, 길 잃은 기사 → 빈 기사의 투구). 싸움의 대가로 칼로리와 피로.
- 장면은 부품으로 나눈다: 흐름·입력은 `ActionScene.js`, 싸움터 그림은 `BattleArena.js`(그 땅의 바닥을 필드와 같은 팩 타일로 굽고 — `MapRenderer` — 둘레에 그 땅의 나무·바위, 가장자리 그늘, 그 땅에 내리는 눈·낙엽·불티·별·재), 화면 위 정보는 `BattleHud.js`(필드 창과 같은 밤색+금 판: 보스 이름 띠와 성나는 지점 눈금, '남은 적' 명패, 얼굴 메달·체력 막대(늦게 따라오는 막대·10% 눈금·회복 띠), 상태이상 알약, 스킬 칸(모양별 그림·키캡·둥근 재사용 시계·다 차면 번쩍), 퀵슬롯, 연타 수, 알림 줄, 체력이 낮으면 붉은 가장자리, 이겼다/쓰러졌다 띠), 효과는 `BattleFx.js`(베기 궤적, 타격 불꽃, 맞으면 하얗게·눌림, 외곽선 굵은 피해 숫자(큰 타격은 노랗게 크게), 쓰러지면 그 색의 조각과 먼지, 나타날 때 흙먼지, 발밑 먼지, 돌진 잔상, 회복 빛). 예고는 터질 때가 가까울수록 테두리가 빨리 뛰고 하얘진다. 탄엔 꼬리가 있다. 보스가 쓰러지면 잠깐 느려진다.
- **균형은 봇으로 지킨다**(`tests/helpers/bots.js`, `tests/unit/action.test.js`): 가만히 있으면 진다. 정리자의 그림자는 피하며 싸우는 봇 50% 이상·때리기만 하는 봇 20% 이하, 레온 결투는 때리기만 하면 진다, 들판 무리는 피하며 싸우면 거의 이긴다.
- 장비 외형: 갑옷은 주인공 옷 두 톤을 바꾼 도트(`src/art/equipLook.js`), 무기는 칼날 색으로 보인다.

## 가게와 주머니 (`content/shop/shops.js`, `src/shop/shop.js`, `src/field/systems/Shops.js`, `src/ui/ShopPanel.js`)

- 나눔: 가게 데이터(무엇을·얼마에·누가·언제) `content/shop/shops.js` → 규칙(순수: 열린 시간, 오늘 파는 것, 사기·팔기·주머니) `src/shop/shop.js` → 필드 부품(주인에게 말 걸면 창) `src/field/systems/Shops.js` → 창 `src/ui/ShopPanel.js`. FieldScene엔 `this.shops.onTalk(id)` 한 줄.
- 가게 주인(`keeper`)에게 E로 말을 걸면 가게 창이 열린다. 그 사람에게 걸린 이야기(퀘스트·이벤트·처음 듣는 대화)가 먼저다. 주인이 그 맵에 없으면(지워졌거나 집에 들어갔으면) 가게도 없다. 시계가 도는 날엔 `hours` 밖이면 "닫았다"는 말풍선.
- 가게 일곱: 그레타네 잡화점(우리 마을), 마이의 과일 좌판·로웬 상인 조합(로웬), 브로크의 대장간(드워프 마을), 넬의 생선 가게(항구), 서리 마을 여관(고르드), 키라의 물약 가게(아스테라).
- 화폐는 동전(닢). 처음 주머니 30닢(`START_PURSE`). 싸워서 이기면 무리 하나당 2닢, 보스 40닢(`BOUNTY`). 팔면 값의 절반(`SELL_RATE`). 가게마다 사들이는 종류(`buys`)가 다르고, 입은 장비·소중한 것은 팔 수 없다.
- 물건마다 `n`(하루에 파는 수)과 `when`(대본 조건, 예: 가죽 조끼는 견습 기사가 된 뒤)을 둘 수 있다. 그날 판 수는 세이브 v12의 `run.shop.sold`.
- 창: 주인 얼굴과 인사말(돌아가며), 주머니, 사기/팔기 탭, 물건 줄(등급 색·값·오늘 남은 수), 고른 것의 큰 그림·설명, 장비면 지금 입은 것과 비교(초록 좋아짐/빨강 나빠짐). 닢이 모자라면 알림 줄이 흔들린다.
- 먹을 것은 `kcal`이 있어 가방에서 U로 직접 먹을 수 있다(체중이 붙고 피로가 조금 풀린다). 동물은 좋아하는 먹이가 다르다(고양이: 말린 생선·짜 먹는 간식, 개: 말린 고기).
- 조사(을/를 등)는 `src/core/util/josa.js`로 받침에 맞춘다.

## 행동 파밍 (`src/farm/`, `content/farm/`)

- 길 맵의 작은 나무에서 E → 벤다(목재). 벤 나무는 그 칸에서 영영 사라진다(`farm.felled`). 바위 무더기에서 E → 돌.
- 같은 행동을 반복하면 정해진 횟수부터 확률로 히든 스킬이 열린다(희귀도·조건은 게임에 공개하지 않음): 우지끈(SR, 벌목) · 단단한 손(R, 채광) · 낮잠 고수(N, 잠) · 먼 길(R, 걷기). 스테이터스 창에 보이고, 전투 능력치에 들어간다.
- 세계가 반응한다: 깊은 숲에서 한 그루라도 베면 엘프를 만날 수 없다. 20그루를 넘게 베면 엘프 마을이 그루터기만 남은 '깊은 숲'이 된다.
- 세이브 v5: `run.farm`.

## 휴대폰 (터치)

- 터치 기기(또는 주소에 `?touch=1`)면 왼쪽 아래 가상 조이스틱, 오른쪽 아래 E·C 버튼이 나온다. 조이스틱은 `phaser4-rex-plugins`(Phaser 4용 Rex 플러그인, 버전 고정)의 VirtualJoyStick만 가져다 쓴다.

- 터치에선 화면 탭이 대화창이 떠 있을 때만 넘긴다(조이스틱을 만져도 걷는 대사가 넘어가지 않게). 전투는 스킬 글자와 적을 직접 누른다(한 번 더 누르면 실행).

## 소리 (`content/audio/`, `src/core/audio/Sound.js`)

- 원본(ogg·wav)은 `assets-src/ninja-adventure/Audio`에 그대로. `npm run assets`가 `tools/build-audio.mjs`로 웹용 ogg + m4a(사파리용)를 만든다(`public/assets/audio`, git 제외). 원본 해시로 캐시해서 두 번째부터는 0.1초. ffmpeg가 없으면 원본을 그대로 복사한다. CI도 같은 해시로 캐시한다.

- 음량 페이드는 숫자 하나를 트윈해서 옮겨 담는다 — 소리 객체를 직접 트윈하면 소리가 먼저 지워졌을 때 장면 전체가 멈춘다(실제로 겪은 버그).
- 소리 끄기/켜기: 오른쪽 위 소리 단추, ESC 메뉴의 옵션 (이 브라우저에 기억). M은 전체 지도다.

## HUD (`src/ui/Hud.js`, `src/ui/Minimap.js`)

- PC 게임처럼 창 틀 안에 둔다: 왼쪽 위 금테 명판(장소·날짜·시각, ◆ 지금 할 일), 오른쪽 아래 키캡 줄(WASD 이동 · E · I · J · C · +− · M · ESC). [M] 키캡을 눌러도 전체 지도가 열린다.
- ESC 메뉴(`ui/PauseMenu.js`): 옵션(소리, 전체 화면) / 플레이 기록 저장(플레이테스트 기록이 켜졌을 때만) / 처음으로 가기(한 번 더 눌러 확인, 진행은 저장된 채 타이틀로). 다른 창이나 대화가 열려 있으면 ESC는 그것을 닫는다. 창이 열린 동안엔 E가 사람에게 가지 않는다.
- 오른쪽 위 작은 지도: 화면 모서리에 붙는다. 얇은 띠 테두리(어두운 바깥선 · 흰 띠 · 그 지역 색 안쪽선 — 마을 금색, 서리 마을 하늘색, 엘프 마을 초록…). 윗줄 가운데엔 이 게임의 문장인 적붉은 까마귀 메달, 지도 아래쪽 안의 얇은 띠에 이름과 넓게·좁게 단추. 보이는 칸 수는 맵의 짧은 쪽을 넘지 않아 늘 꽉 찬다. 소리 단추는 그 왼쪽. 늘 켜져 있다. 지금 맵(마을·길·건물 안)을 칸 하나 = 4×4 화소로 그리고(풀결·나무 덩이·건물 종류별 지붕 색과 외곽선), 이름 있는 건물엔 흰 동그라미 휘장(종탑 종·빵집 빵·대장간 칼과 방패·잡화점 물약·꽃집 꽃·초소 투구·우리 집·여관 침대… `content/art/mapIcons.js`, 이름으로 정한다. 주인이 지워져 이름이 바뀐 집엔 없다), 나(금색)·사람(흰 점)·할 일이 남은 사람(노란 점)·몬스터(붉은 점). +/− 키, 마우스 휠, 지도 아래 단추로 넓게·좁게(3단계).
- M: 전체 지도(`ui/WorldMapPanel.js`). 세계(`content/world/world.js`)의 칸을 그 땅 색으로, 길은 선으로. 길 밖은 흐릿한 가장자리, 안 가 본 칸은 안개, 마을 이름은 가 보기 전까지 깨져 있다. 나(깜빡이는 금색 점)와 지금 할 일의 목적지(별). 가 본 층만 Q·E로 넘긴다. 열린 동안 주인공은 멈춘다.
- 알림(퀘스트·단서)은 위쪽 가운데 금테 띠로 뜬다. 살펴볼 수 있는 곳 위엔 작은 E 키캡.
- 휴대폰(터치)에선 키캡 줄 대신 화면 버튼이 나온다. 오른쪽 위 소리 버튼은 어디서나 늘 떠 있다.

## 에셋 파이프라인

```
assets-src/ (CC0 원본)  ──npm run assets──►  public/assets/gen/  ──Boot──►  Phaser 텍스처
                         재채색·덧그리기            manifest.json            물체 프레임·애니메이션 등록
```

- `npm run dev`, `npm run build` 전에 자동으로 돈다(predev / prebuild). 결과물은 git에 올리지 않는다.
- **캐릭터 추가**: 팩에서 바탕 캐릭터를 `assets-src/.../Actor/Characters/<이름>/`에 복사 → `content/characters/<id>.js`에 `sprite: { base, recolor, edits }`. 바꾸려는 색이 원본에 없으면 테스트가 실패한다(오타 방지).
- **물체 추가**: 팩 시트에서 사각형을 찾아 `content/art/pack.js`의 `OBJECTS`에 `rect`(그림)와 `foot`(충돌) 등록 → 맵에 `O('이름', x, y)`.
- **맵 수정 후**: `npm run validate`가 막힌 칸, **걸어서 닿을 수 없는 인물·물건·구역**까지 잡는다.

## 일러스트와 대화창 (`content/cg.js`, `src/ui/DialogBox.js`, `src/ui/CgLayer.js`)

- 진짜 일러스트가 있는 인물(`PORTRAITS`)은 대화창으로 말할 때 오른쪽 뒤에 상반신이 선다. 주인공·내레이션 차례에는 어둡게 남는다. 없는 인물은 대화창 안에 팩의 작은 도트 얼굴.
- 파일은 인물마다 폴더 하나: `public/assets/characters/<사는 곳>/<인물>/`(portrait = 기본, 그 밖은 표정). 코드로 그린 임시 일러스트는 쓰지 않는다.
- 배경을 지운 그림은 넣기 전에 `node tools/fill-portrait-holes.mjs 입력.png 출력.png`로 안쪽 구멍을 메운다. 배경 지우기가 속눈썹·머리카락을 반투명하게 남겨 뒤의 풀밭이 초록으로 비치기 때문이다(바깥 테두리는 그대로 둔다). 그다음 `cwebp -q 92 -alpha_q 100 -exact`로 webp.
- 이벤트 CG: `CG`에 파일, 또는 `bg`(배경 CG) + `figure`(인물). 생김새(색·테두리·글자)는 `src/ui/kit.js`.

## 세계의 시간 (`src/core/util/worldTime.js`)

- 다운로드 전(웹)은 게임 안 시계, 다운로드 후(데스크톱)는 현실 시간. 계절·하루의 빛·조수·떠돌이·몬스터·은하의 종·생활 쿨다운·타이틀이 모두 `worldDate(run)`을 따른다.
- 게임 안 달력: 1일째 = 11월 10일(수확제 철, 늦가을). 21일째 = 12월 1일(초겨울), 30일째 첫눈 축제. 타이틀 오른쪽 위엔 'n일째'.
- 잠: 시계가 도는 날엔 침대에 들면 12시간이 흐른다(피로 0, `SLEEP_MINUTES`). 밤 10시에 자면 다음 날 아침 10시.

## 게임 시계와 하루 일과 (`content/world/clock.js`, `src/field/systems/Clock.js`·`Schedules.js`)

- 시계가 도는 페이즈(`clock: true`)에서만 게임 시간이 흐른다. 게임 1분 = 현실 1초(하루 24분). 대화·컷신·수첩 중엔 멈춘다. 세이브의 `run.time { day, minute }`.
- 페이즈의 `day`(그날 날짜)와 `startAt`(시작 시각, 없으면 time에 따라 09:00/20:00)은 처음 들어설 때만 맞춘다.
- 조명은 시각을 따라 새벽·낮·노을·밤이 이어진다(`Lighting.setClock`). 시계 없는 이야기 장면(축제의 밤, 종탑의 밤)은 그 페이즈의 `time` 그대로.
- 일과로 사는 사람이 지워지면 그 사람의 첫 일터(집이 아닌 첫 장소)에 흔적(`remnant`)이 남는다(`Schedules.placeRemnants`, `workSpot`). 빈자리 찾기가 시계 도는 날에도 이어진다.
- 하루 일과: 인물 파일의 `schedule`(시각 순서, `at`·`mode`·`say`·`task`·`home`·`when`). 시각이 바뀌면 길찾기(A*, `systems/Path.js`)로 걸어서 옮기고, `home`이면 맵 `objects`의 `residents`에 그 사람이 있는 건물 문으로 들어가 필드에서 사라진다. 페이즈가 직접 배치한 인물은 일과를 쓰지 않는다.
- 잠: 시계가 도는 날 우리 집 침대에서 E → 12시간이 흐른다. 자정을 넘겼으면 같은 하루(또는 `phase.next`)를 새로 시작한다.
- 검증: 일과의 시각 형식, 장소, 걸을 수 있는 칸, 집 문 앞.

## 마을 습격 (`content/raids.js`, `src/field/systems/Raids.js`, `src/field/systems/FieldBattle.js`)

- 시계가 도는 날, 정해진 날·시각이 지나면 습격이 온다. `sign`은 장면만(8일 아침 털린 채소밭), `raid`는 경고 장면 → 무리가 북쪽 길에서 나타나 길찾기로 목표(곡식 더미·빵집)까지 걷는다.
- 오크와 부딪히거나 곁에서 E를 누르면 그 자리의 싸움(`FieldBattle`: 필드를 잠재우고 Action을 띄웠다가 깨운다). 곁(5칸 안)의 오크도 같이 덤빈다. 이기면 그 오크들은 달아나고, 물러나면 그대로 간다. 다 쫓아내면 지킨 것, 하나라도 목표에 닿으면 못 지킨 것. 목표 줄은 "○○을(를) 지켜라". 혼자 싸운다.
- 날짜: 털린 밭(8일, 1장) · 정찰대(15일, 2장) · 토르크(24일, 3장, 예고를 읽어야 이긴다).
- 결과는 `raid.<id>.won/.lost/.over`와 `won`/`lost`의 플래그·호감도로 남는다(`granary.looted`, `bakery.burned`). 못 지킨 습격이 `FALL_AFTER`번 쌓이면 `village.fallen`.
- 오크·토르크는 팩의 Hunter를 초록 피부로 재채색하고 엄니(토르크는 부러진 엄니 + 붉은 망토)를 덧그렸다(`sprite.shareBase`).
- 아직 없는 것: 불탄 빵집·털린 곡식 더미의 그림. 브라우저 콘솔 `__ud.raid('scouts')`로 바로 불러 볼 수 있다.
- 검증: 시각 형식, 화자, 출발점·목표가 걸을 수 있는 칸인지.

## 퀘스트와 단서 수첩 (J)

- 퀘스트 단계의 `goal`(목적지): `{ npc }` `{ spot }` `{ zone }` `{ place: 거점 }`, 목록이면 조건이 맞고 지금 맵에서 찾을 수 있는 첫 것(`src/field/goals.js`). 작은 지도에 금색 별(같은 맵), 다른 마을이면 그쪽 가장자리 화살표. 단계에 `count: { of: { 인물: 플래그 }, n }`이면 목표 줄에 (n/m)과 남은 사람 이름.
- 머리 위 이름(`ui/NameTags.js`): 7칸 안의 사람. 그 사람에게 할 일이 남았으면 금색.
- 퀘스트: `content/quests/`(막마다 파일), 돌리는 곳 `src/field/systems/Quests.js`. 받는 길은 주는 사람(`giver`)에게 말 걸기, `start.auto`(조건이 맞으면 저절로). 단계의 `done`: `{ flag }` `{ talk: 인물 }` `{ zone }` `{ when: 대본 조건 }`. 진행 중인 메인 퀘스트의 지금 단계가 왼쪽 위 할 일이 된다.
- 단서: `content/clues.js`의 `{ id, title, text, when }`. 조건이 맞는 순간 수첩에 적히고 알림이 뜬다(`src/field/systems/Clues.js`). 그때 알 수 있는 것만 쓴다.
- 수첩 창: `src/ui/NotebookPanel.js`. J(휴대폰은 J 버튼)로 열고, ←→ 쪽, ↑↓ 단서 고르기. 열려 있는 동안 주인공은 멈춘다.
- 퀘스트·단서는 걸으며 듣는 대사 중에도 따라잡는다.

## 저장과 확장성 (DB 대비)

```
게임 로직 ──► WorldMemory ──► SaveRepository ──► StorageAdapter
                                 (메모리 캐시)      ├─ LocalStorageAdapter (지금, 웹)
                                                   ├─ MemoryAdapter (테스트)
                                                   ├─ TauriFileAdapter (예정, 데스크톱: 게임 폴더에 세이브)
                                                   └─ RemoteAdapter (예정, 서버 DB)
```

- **어댑터 계약**은 비동기 `read / write / remove` 셋뿐이다(`core/storage/StorageAdapter.js`). 원격 DB로 바꿀 때 어댑터 하나만 새로 쓰고 `core/storage/index.js`에서 고른다.
- **Repository**는 시작할 때 한 번 읽어 메모리에 올리고, 이후 쓰기는 비동기로 흘려보낸다. 게임 루프가 네트워크를 기다리지 않는다.
- **세이브 스키마**는 버전이 있다(`core/save/SaveSchema.js`). 필드를 바꾸면 `VERSION`을 올리고 `MIGRATIONS`에 변환을 추가한다. 이 구조가 그대로 DB 테이블/문서의 기준이 된다.
  - `world`: 지워짐, 로드 횟수 — 세계의 기억
  - `run`: 장, 페이즈, 플래그, 호감도, 퀘스트(`quests`), 단서(`clues`), 게임 시계(`time`), 고향 페이즈(`home`) — 현재 진행. v6에서 퀘스트와 단서 수첩, v7에서 시계, v8에서 고향 페이즈가 붙었다
  - `meta`: 생성·수정 시각, `playerId`(계정 연동 자리)
- **공유 데이터**(서버 공통 붕괴, 정신체 도움, 도달률)는 `core/world/GlobalWorld.js` 한 곳으로만 나간다. 지금은 꺼져 있다.
- 조작 정책: 개인 데이터는 막지 않는다. 공유 데이터만 서버에서 상한 검증.

## 새 콘텐츠 추가하기

**인물**: `content/characters/<id>.js` 작성 → `index.js`에 등록. 새 머리·소품이 필요하면 `content/art/layers.js`에 레이어 추가. 미리보기로 확인.

**장**: `content/chapters/<장>/phases.js`, `script.js` 작성 → `chapters/index.js`에 등록. 이전 장 마지막 컷신의 `end.next`로 이어 준다.

**이벤트**: 해당 페이즈의 `events`에 한 줄 + `script.js`에 컷신 하나.

**맵**: `content/maps/village.js`의 `build()`에 사각형 배치. 마을 동쪽 20칸은 울타리 너머 들판이다: 맵의 `crops`(밀 `wheat`·그루터기 `stubble`·물 뺀 논 `paddy`·채소 고랑 `veg`)를 `MapRenderer.drawCrops`가 흙 위에 얹는다(팩 그림, `pack.js`의 `CROPS`). 수확제 철이라 밀밭은 거의 다 베어 건초 더미가 서 있고 한 이랑만 남았다. 오토네 농가, 낮은 나무 난간(`fence_h`). 장소(`spots`)와 구역(`zones`)에 이름을 붙이면 대본에서 이름으로 부른다.

추가한 뒤엔 항상 `npm run check` (검증 + 단위 테스트 + 빌드).

## 테스트

원칙: **"망가졌나?"는 기계가, "재밌나?"는 사람이** 확인한다. 기능을 넣을 때 테스트를 같이 넣는다.

| 층 | 무엇을 | 어디 | 명령 | 시간 |
| --- | --- | --- | --- | --- |
| 콘텐츠 검증 | 라벨 오타, 막힌 칸의 인물·물건, 지워진 사람이 말하는 대사, 켜지지 않는 플래그, 소프트락 | `tools/lib/validateContent.mjs` | `npm run validate` | 1초 |
| 단위 | 지워짐 규칙, 세이브 이관·저장 실패, 대본 조건, 이벤트 계기, 날짜 유틸, 에셋 빌드·재채색·종탑 변형, 물체 사각형, 맵 충돌, 자동 타일, 타이틀 장면 설정, 대사 깨짐·걷는 대사·빈자리, 전체 지도·길 맵 생성 | `tests/unit/` | `npm test` | 3초 |
| 논리 플레이스루 | **모든 지워짐 조합(16가지)**으로 봇이 프롤로그를 끝까지 플레이 | `tests/unit/content.test.js` | `npm test` | 포함 |
| E2E | 빌드한 실제 게임을 헤드리스 Chromium으로 완주 → CONTINUE → 가장 아낀 사람이 지워졌는지, RESET 후에도 안 돌아오는지 | `tests/e2e/` | `npm run test:e2e` | 2~3분 |
| 플레이테스트 | 사람이 실제로 해 본 기록: 어디서 머물고 헤맸나, 누구에게 말을 걸었나, 언제 껐나, 누가 지워졌나 | `src/core/playtest/` | `?playtest`로 열고 `node tools/playlog-report.mjs` | — |

- **플레이테스트 기록** (`src/core/playtest/PlayLog.js`): `?playtest`로 한 번 연 브라우저에서만 켜진다. 세이브와 따로(`ud.playlog`) 페이즈·장면·말 걸기·살펴보기·줍기·싸움·로드와 지워짐·10초마다의 발자취(`field/systems/PlayTrace.js`)·창 닫음을 남긴다. ESC 메뉴의 '플레이 기록 저장'으로 내려받고 `tools/playlog-report.mjs`(요약은 `src/core/playtest/summary.js`, 순수 함수)로 읽는다. 진행법은 [플레이테스트.md](플레이테스트.md).
- **CI**: GitHub에 푸시하면 `.github/workflows/ci.yml`이 위 네 층을 자동으로 돌린다. 실패하면 리포 Actions 탭에서 원인과 스크린샷을 본다.
- E2E는 처음 한 번 `npx playwright install chromium`이 필요하다.
- E2E는 게임이 여는 `window.__game`, `window.__ud`로 상태를 읽고 플레이어를 순간이동시킨다(`tests/e2e/game.js`).
- 버그를 고치면 **그 버그를 재현하는 테스트를 먼저** 넣는다(예: `script-runner.test.js`의 aff+flag 회귀 테스트).
- 새 이벤트 계기(trigger)를 만들면 `event-director.test.js`에, 새 장을 만들면 `content.test.js`의 플레이스루에 추가한다.

## 개발 명령

```bash
npm run dev                              # 웹 개발 서버
npm run build                            # 웹 빌드 → dist/
npm run tauri dev                        # 데스크톱 창으로 실행 (Rust 필요)
npm run tauri build                      # EXE
npm run check                            # 검증 + 단위 테스트 + 빌드 (커밋 전에)
npm run validate                         # 콘텐츠 검증
npm test                                 # 단위 테스트 (npm run test:watch: 저장할 때마다)
npm run test:e2e                         # 실제 게임 자동 플레이
npm run assets                           # 에셋 빌드 (dev/build 전에 자동)
```

브라우저 콘솔: `await __ud.wipeAll()` 후 새로고침하면 세계까지 완전 초기화. `__game`은 Phaser 게임 객체.
