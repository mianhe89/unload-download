# 구현 정리

기획은 [기획서.md](기획서.md), 그림 규칙은 [아트디렉션.md](아트디렉션.md)에 있다. 이 문서는 **코드가 어떻게 짜여 있고, 무엇을 어디에 추가하는가**를 다룬다.

## 한눈에

```
화면 흐름   Boot ──► Title ──► Field ⇄ UI(겹침)
                      ▲          │
                      └──────────┘  챕터 끝 / 타이틀로
                     (예정) Field ──► Battle(사이드뷰) ──► Field
```

- **Field**: 탑다운으로 걸어 다니는 곳. 한 번에 한 페이즈(어디서·누가·무슨 일이)를 돌린다.
- **UI**: Field 위에 겹쳐 도는 씬. 대화창·말풍선·HUD. 카메라 배율과 무관하게 글자가 선명하다.
- **Battle**: 필드에서 조우하면 넘어가는 사이드뷰 전투(포켓몬 구조 + 라테일·에픽세븐 연출). 아직 없다.

## 핵심 규칙: 지워짐 (`src/core/world/WorldMemory.js`)

- **CONTINUE = 로드**. 누적 로드 +1, 그리고 마을 사람 한 명이 지워진다.
- 누가 지워지나: 지워질 수 있는 사람(`erasable: true`) 중 **호감도가 가장 높은 사람**. 동점이면 `ERASE_ORDER` 순서.
- **RESET & START**는 진행(run)만 처음으로 돌린다. 세계(world)의 지워짐과 로드 횟수는 남는다.
- 지워진 사람은 필드에 배치되지 않고, 그 자리에 `remnant`(흔적 소품)가 남는다. 대본은 `unlessErased` / `ifErased` 조건으로 갈린다.

## 페이즈와 이벤트 (`content/chapters/*/phases.js`)

선택창은 없다. 갈림길은 플레이어의 행동이 만든다.

```js
{ id: 'hort.spill', when: { unlessErased: 'hort' }, trigger: { near: 'hort', r: 4 }, run: 'festival.hort_spill' }
```

| trigger | 뜻 |
| --- | --- |
| `{ near, r }` | 인물/장소 근처에 가면 (r: 타일) |
| `{ zone }` | 구역에 들어서면 (`maps/village.js`의 zones) |
| `{ timer }` | 페이즈 시작 후 n초 |
| `{ afterFlag, delay }` | 플래그가 켜지고 n초 뒤 |
| `{ dwell, r, seconds, ticks }` | 그 곁에 누적 n초 머물면. ticks로 도중 말풍선 |
| `{ idle, near, r, minTime }` | 그 곁에서 가만히 n초 |
| `{ pickedAll, near?, r? }` | 흩어진 물건을 다 주웠으면 (+그 사람에게 가면) |
| `{ count: [플래그…], n }` | 플래그 n개 이상 |
| `running: true` (다른 계기에 덧붙임) | 뛰어서 지나갈 때만. 같은 방향키를 빠르게 두 번 누르면 달린다(`RUN_SPEED`·`RUN_TAP`) |

- 이벤트는 한 번만 실행되고 `done.<id>` 플래그로 기억된다(이어하기 후에도 반복되지 않음).
- `when`은 대본 조건과 같은 문법이다(아래).
- 인물 배치에도 `when`을 달 수 있다(예: 셀레나와 이야기한 뒤에만 루가 있음).
- E 키로 말을 걸면 `talk.<페이즈>.<인물>` 컷신이 있으면 처음 한 번 실행, 이후엔 그 인물의 혼잣말.

## 컷신 대본 (`content/chapters/*/script.js`)

```js
'festival.hort_thanks': [
  T('hort', '오, 다 주워왔냐!'),
  T('tom', '어라. 이 얘기 아까도 하지 않았나?', { minLoads: 1 }),
  { aff: { hort: 2 }, flag: 'ev.hort' },
],
```

| 노드 | 뜻 |
| --- | --- |
| `N(문장)` / `T(인물, 문장)` | 내레이션 / 대사 |
| `T(인물, 문장, { face: '표정' })` | 그 표정의 일러스트로 말한다(`content/cg.js`의 `PORTRAITS.<인물>.faces`) |
| `B(인물, 문장)` | 말풍선 (대화창 없이) |
| `WALK` (라벨 첫 줄) | 걸으며 듣는 대사. 아래 참고 |
| `{ fx }` | `shake` `bell` `flash` `fade` `glitch` |
| `{ cg: 'id', tint? }` / `{ cg: null }` | 이벤트 CG 띄우기 / 내리기(`content/cg.js`). 컷신이 끝나면 저절로 내려간다. 걷는 대사 중에는 띄우지 않는다 |
| `{ aff: { 인물: n } }` | 호감도 |
| `{ flag }` | 플래그 켜기 (aff와 한 노드에 같이 써도 된다) |
| `{ act: 'spawnPickups', group, prop, items, expire? }` | 물건 흩뿌리기 |
| `{ act: 'spawnNpc', id, at \| near:'player', offset }` | 인물 등장 |
| `{ act: 'walkTo', id, path: [[x, y], …], wait? }` | 경유지를 차례로 걸어가 그 자리에 머문다(사라지지 않음). 경유지가 막힌 칸이면 검증에서 잡는다 |
| `{ act: 'walkAway', id, to }` / `{ act: 'despawn', id }` | 퇴장 |
| `{ act: 'battle', enemies, party, note?, winLine?, flag? }` | 그 자리에서 사이드뷰 전투(`systems/FieldBattle.js`). 이기면 flag. 지고 물러나면 그대로 다음 노드로(뒤 노드는 ifFlag로 갈린다) |
| `{ phase }` | 같은 장의 다음 페이즈로 |
| `{ end: 'title', next: { chapter, phase } }` | 타이틀로, 다음 이어하기 지점 지정 |

조건(모든 노드): `ifErased` `unlessErased` `ifErasedAny` `minLoads` `maxLoads` `ifFlag` `unlessFlag`(이름 하나 또는 목록) `afterTime`·`beforeTime`('HH:MM') `minDay`·`maxDay` `ifQuest`('id' / 'id.done' / 'id.step2') `anyOf: [조건…]`(하나라도 맞으면)
문장 안 치환: `{bells}`(13 + 로드 횟수), `{loads}`, `{lastErased}`(가장 최근에 지워진 사람 이름)

### 대사의 두 방식

| | block (기본) | walk (`WALK`) |
| --- | --- | --- |
| 플레이어 | 멈춘다 | 계속 걷는다 (물건도 주울 수 있다) |
| 표시 | 아래 대화창 + 작은 도트 얼굴 | 화자 머리 위 말풍선, 내레이션은 허공에 떠오르는 글 |
| 넘기기 | 키를 눌러야 | 저절로 (Space로 빨리) |
| 놓침 | 없음 | 화자에게서 6칸 넘게 멀면 `…`만 흐릿하게, `missed.<라벨>` 플래그 |
| 쓰는 곳 | 에다·종소리·미아의 '에다?'·셀레나·루·정리자·종탑 | 나머지 전부, 모든 `talk.*`, 배경 주민끼리의 엿듣는 대화 |

페이즈 전환·장 끝은 block 장면에서만 일어난다(테스트가 지킨다).

### 지워진 이름

마을 사람 입에서 지워진 사람의 이름은 `▒▓` 같은 깨진 글자로 나온다(길이는 같고, 같은 이름은 늘 같은 모양). 내레이션과 주인공은 온전히 말한다. 지워진 사람 = 로드로 지워진 사람 + 대본상 사라진 사람(`gone: { notInPhases }`, 에다는 수확제 밤에만 있다). 대본에 이름을 그냥 쓰면 엔진이 알아서 깬다.

### 빈자리 찾기 (1장)

지워진 사람의 흔적을 E로 살펴보면 `found.<id>`, 목표 옆에 `빈자리 n/m`. 다 찾으면 `found.all` → 종탑에서 한 줄이 더 보인다. 강제는 아니다.

## 여러 마을 (이야기 필드의 맵)

- 페이즈의 `map`(기본 `'village'`)이 그 페이즈의 맵이다(`content/maps/index.js`의 `MAPS`). 맵 모듈은 같은 꼴을 따른다: `id` `W` `H` `FOG` `terrain` `objects` `solids` `exits` `entry(dir)` `isSolidPx` `isSolidTile` `spots` `zones`.
- 다른 마을에 들르기: 전체 지도의 거점에 `field: '<맵 id>'`가 있으면, 길 맵에서 그 칸에 들어설 때 지금 장의 `visit: true` 페이즈(조건 `when`이 맞는 것)로 들어간다(`src/world/visits.js`). 없으면 길 맵의 빈 거점 그대로다.
- 들르는 페이즈는 `keepTime: true`로 시계를 이어 간다. 고향에서 길로 나갈 때 돌아올 페이즈가 세이브 v8의 `run.home`에 남는다(다른 마을에서 이어하기를 해도 고향으로 돌아갈 수 있다).
- 인물 파일의 `home`(사는 맵, 기본 `'village'`): 그 맵에 있을 때만 하루 일과를 산다. `away`(조건): 그 조건인 동안은 마을에 없다.
- 1장부터 들를 수 있는 마을: 빈 마을(사람 없이 문패와 이름 벽만), 서리 마을(사나운 마을. 해 질 녘마다 오크가 내려오고, 브렌나와 둘이서 막는다), 항구(마를로·넬), 드워프 마을(브로크·헬가). `content/places/`에 두고 장마다 섞는다.
- 항구의 남쪽 끝(선착장)과 드워프 마을의 북쪽 끝(갱도)은 길 맵의 그 거점 칸으로 이어진다. 배와 계단은 길 맵에 있다.
- 엘프 마을은 아직 길 맵 그대로다(숲을 베면 사라지는 규칙이 길 맵에 있다).
- 습격은 그 습격의 `map`(기본 우리 마을)에만 온다. `daily: true`면 날마다 그 시각에.

## 마을 밖으로 (전체 지도와 길 맵)

- 전체 지도는 `content/world/world.js`. 칸 하나 = 맵 하나, 거점 사이는 4~6칸.
- 마을(이야기 필드)의 출구는 `village.exits`. 페이즈가 `exits: ['n']`처럼 열어줄 때만 안개가 걷히고 지나갈 수 있다. 지금은 1장부터 북쪽 길이 열린다.
- 출구 끝을 밟으면 `Area` 씬이 그 칸의 맵을 `buildArea(layer, at)`로 만들어 띄운다. 맵 끝 출구를 밟으면 이웃 칸으로, 시작 마을 칸으로 돌아가면 `Field`로 돌아간다(들어온 쪽 출구 자리에 선다).
- 바닥은 기후 테마(`pack.js THEMES`: 마을·풀·눈·모래·마른 땅)로 그린다. 바닥 시트의 블록이 같은 배치로 반복돼서 흙길 자동 타일 좌표를 옮기기만 하면 눈길·모랫길이 된다.
- 처음 간 칸은 `visited.<칸>` 플래그가 켜지고 그곳 설명이 허공에 떠오른다.
- 길 맵마다 살펴볼 거리가 하나씩 있다(E). 거점 옆 칸은 이정표(가 본 적 없는 마을 이름은 깨져 있다), 곁가지 구역은 그 지형지물(`found.side.<칸>`), 나머지 길은 기후별 흔적 글(`content/world/features.js`, `{loads}` 치환).
- 층 사이 계단: 드워프 마을 ↔ 갱도 입구, 고대 유적 ↔ 유적 아래 회랑. 계단을 밟으면 넘어간다. 지하와 은하는 늘 밤처럼 어둡다.
- 은하: 종 걸린 절벽의 종을 열세 번. 실제 밤(20시~4시)이고 `found.all`이어야 열린다(`ringBell`). 은하 쪽엔 돌아가는 계단.
- 땅 색 테마: 갱도(어두운 흙), 용암(달궈진 땅), 은하(보랏빛) — 바닥 위에 곱하기로 색을 덮는다.
- 바닷길: 항구 남쪽은 물가, 선착장 끝의 배에서 E → 바다 칸으로. 바다에선 배를 타고 다니고(물 위 어디든, 바위만 막힘), 항구 쪽 출구로 돌아오면 배 옆에 내린다. 바다 유적은 실제 시각의 조수(12시간 25분 주기 중 3.1시간 썰물, `lowTide`)에 따라 썰물이면 지붕이 섬처럼 드러난다.
- 떠돌이: 길 맵에 칸·날짜로 정해진 사람이 가끔 있다(같은 날 같은 칸이면 같은 사람). 나그네는 추운 길, 상인은 따뜻한 길, 정신체는 어디서든. E로 말을 걸면 말풍선으로 한 줄씩. 정신체는 가장 가까운 '아직 안 간 곁가지' 방향을 알려주고(`spiritHint`), 마을 사람과 달리 지워진 이름을 온전히 말한다.
- 길 맵 안 저장: 세이브 v3의 `run.where`. 길 맵에 들어가면 그 칸이 저장되고, 마을로 돌아오면 비워진다. 이어하기(로드 대가는 그대로)는 그 칸 가운데서 시작한다.
- 몬스터: 길 맵에 칸·날짜로 정해진 무리가 보이고, 부딪히면 전투. 이기면 `beat.<칸>.<날짜>`(보스는 `beat.boss.<칸>`, 영구).
- 보스 자리(`content/battles/encounters.js`의 `BOSSES`): `when`(나타나는 조건), `party`(같이 싸우는 사람), `flag`(이기면 켜짐). 2장의 길 잃은 기사는 `surface:5,10`(옆 마을 가는 안개 길)에서 나·루 둘이서.

## 전투 (`src/battle/`, `src/scenes/battle/`)

- 사이드뷰 턴제. 아군 3명(나·셀레나·루). 속도 게이지(0→100)가 먼저 차는 쪽이 행동하고, 위에 앞으로의 차례 7개를 보여준다(`preview`).
- 스킬 3개(1·2·3), ←→ 대상, Enter 실행. 같은 숫자를 두 번 누르면 바로 실행. 쿨다운 중인 스킬은 흐리게.
- 속성: 불 > 바람 > 땅 > 불, 빛 ↔ 어둠 (×1.3 / ×0.8).
- 운은 회피 하나뿐이고 타마다 따로 판정한다 — 다단 히트는 회피형(마른 몸)이, 한 방은 통통한 몸(체력·방어·묵직한 일격)이 유리. 체형은 `run.body`(아직 정하는 방법 없음, 기본 보통).
- 보스(정리자의 그림자, 검은 성 앞)는 큰 기술을 한 차례 먼저 예고한다: 먼지 털기(한 사람 6타) → 쓸어내기(전원 강타, 방어하면 절반) → 치우기(차례 밀기). 방어·도발·늦추기·회복으로 대응한다.
- **밸런스는 자동 대전으로 지킨다**: 예고를 무시하는 AI는 60판 중 25% 미만, 예고를 읽는 AI는 60% 넘게 이겨야 한다(지금 0% / 97%). 일반 몬스터는 생각 없이 싸워도 20판 중 19판 이상.
- 지면: '되돌리기'(R) = 로드. 로드 횟수가 오르고 누군가 지워지고, 같은 전투를 다른 시드로 다시. '물러나기'(Esc)는 길 맵으로.
- 주인공 능력치는 생활 상태(`run.life`)에서: 체형(체중·근육) + 마음가짐 + 피로 (`battleStats`).
- 궁극기(4번): 맞히거나 맞으면 게이지가 차고(타마다 +9 / +6) 가득 차면 쓴다. 쓰면 컷인(얼굴·기술명·한마디). 나: 이름을 부른다(강타 + 적의 예고를 지운다) · 셀레나: 기사단의 성벽(전체 공격 + 아군 전원 방어) · 루: 멈춘 시간(전체 공격 + 게이지 -50).
- 화상: 불 기술(셀레나 휩쓸기, 불짐승 포효)에 맞으면 2차례, 자기 차례 끝마다 최대 체력의 6%. 저항(통통·근육질 체형, 여유 마음가짐)만큼 버틸 확률.
- 싸움의 대가: 전투가 끝나면 칼로리를 쓰고 피로 +8 (생활 → 체형으로 이어진다).
- 아직 없는 것: 전투 보상(재료·장비), 다른 상태이상.

## 생활 (`src/life/`, `content/life/`)

- 선택창 없이 마을의 자리에서 E: 빵집 진열대(꿀빵, 호르트가 지워지면 없다) · 겨울 장 좌판(군밤, 3장) · 집 앞(집밥, 잠) · 우물(물 긷기) · 허수아비(목검). 밤엔 잠만.
- 행동마다 체중(열량)·근육·피로·마음가짐(여유·부지런함·단단함)이 조금씩 움직이고, 같은 행동은 실제 시간 쿨다운(15~60분)이 있다. 걸으면 조금씩 빠진다.
- 체형은 체중·근육으로 정해지고(마른·보통·근육질·통통), 마음가짐은 한쪽이 3 이상 앞서면 그 성향(아니면 균형). 피로 70 이상이면 공격·속도 -10%.
- C(또는 Tab): 스테이터스 창 — 체중·근육·피로, 체형과 전투 수치, 마음가짐과 보정. 숨기는 수치 없음.
- 세이브 v4: `run.life` (v3에서 이관 시 보통 체형으로 시작).
- 체형이 도트에 보인다: `npm run assets`가 주인공 시트에서 체형별 도트(me@thin·me@muscle·me@chubby)를 만든다(`tools/lib/body-edit.mjs`: 앞·뒤 모습은 볼·몸통, 옆모습은 몸통만 1px 넓히거나 좁힘). 필드·전투·타이틀 모두 현재 체형으로 그린다.
- 생활 자리는 어느 페이즈의 사람과도 겹치지 않게 테스트가 지킨다(E가 사람에게 가지 않게).

## 가방과 선물 (`content/items.js`, `src/life/bag.js`, `src/ui/BagPanel.js`)

- I: 가방. 먹을 것·재료·소중한 것. 재료(목재·돌)는 행동 파밍의 것을, 소중한 것(에다의 반지, 리네의 화관)은 플래그를 보고 보여 준다.
- 얻는 곳: 빵집 진열대(꿀빵 하나는 먹고 하나는 가방에), 3장 겨울 장 상인의 좌판(군밤). 생활 행동의 `item`.
- 선물: 사람 곁에서 가방을 열고 Enter. 선택창이 아니라 플레이어가 곁에 가서 정한다. 사람마다 반가움이 다르고(`likes`), 같은 사람에게는 하루 한 번. 반응은 말풍선뿐, 수치는 보이지 않는다.
- 세이브 v9: `run.bag { items, gifted }`.

## 행동 파밍 (`src/farm/`, `content/farm/`)

- 길 맵의 작은 나무에서 E → 벤다(목재). 벤 나무는 그 칸에서 영영 사라진다(`farm.felled`). 바위 무더기에서 E → 돌.
- 같은 행동을 반복하면 정해진 횟수부터 확률로 히든 스킬이 열린다(희귀도·조건은 게임에 공개하지 않음): 우지끈(SR, 벌목) · 단단한 손(R, 채광) · 낮잠 고수(N, 잠) · 먼 길(R, 걷기). 스테이터스 창에 보이고, 전투 능력치에 들어간다.
- 세계가 반응한다: 깊은 숲에서 한 그루라도 베면 엘프를 만날 수 없다. 20그루를 넘게 베면 엘프 마을이 그루터기만 남은 '깊은 숲'이 된다.
- 세이브 v5: `run.farm`.

## 휴대폰 (터치)

- 터치 기기(또는 주소에 `?touch=1`)면 왼쪽 아래 가상 조이스틱, 오른쪽 아래 E·C 버튼이 나온다. 조이스틱은 `phaser4-rex-plugins`(Phaser 4용 Rex 플러그인, 버전 고정)의 VirtualJoyStick만 가져다 쓴다.
- 터치 입력은 `src/ui/touch.js`의 상태로 모여 키보드와 같은 자리(Player.pressed/justPressed)로 들어간다.
- 터치에선 화면 탭이 대화창이 떠 있을 때만 넘긴다(조이스틱을 만져도 걷는 대사가 넘어가지 않게). 전투는 스킬 글자와 적을 직접 누른다(한 번 더 누르면 실행).

## 소리 (`content/audio/`, `src/core/audio/Sound.js`)

- 원본(ogg·wav)은 `assets-src/ninja-adventure/Audio`에 그대로. `npm run assets`가 `tools/build-audio.mjs`로 웹용 ogg + m4a(사파리용)를 만든다(`public/assets/audio`, git 제외). 원본 해시로 캐시해서 두 번째부터는 0.1초. ffmpeg가 없으면 원본을 그대로 복사한다. CI도 같은 해시로 캐시한다.
- 효과음은 Boot에서 미리, 음악은 장면에 들어갈 때 그 곡만 받는다(첫 화면을 가볍게).
- 이야기 페이즈·길 맵 기후·거점·전투(일반/보스)마다 음악, 추운 곳은 바람·바다는 파도가 깔린다. 종·예고·타격·회피·회복·승패·은하 문에 효과음.
- 음량 페이드는 숫자 하나를 트윈해서 옮겨 담는다 — 소리 객체를 직접 트윈하면 소리가 먼저 지워졌을 때 장면 전체가 멈춘다(실제로 겪은 버그).
- M: 소리 끄기/켜기 (이 브라우저에 기억).

## HUD (`src/ui/Hud.js`)

- PC 게임처럼 창 틀 안에 둔다: 왼쪽 위 금테 명판(장소·날짜·시각, ◆ 지금 할 일), 오른쪽 아래 키캡 줄(WASD 이동 · E · J · C · M). [M] 키캡은 눌러도 소리가 꺼지고 켜진다.

- 휴대폰(터치)에선 키캡 줄 대신 화면 버튼이 나온다. 오른쪽 위 소리 버튼은 어디서나 늘 떠 있다.

## 에셋 파이프라인

```
assets-src/ (CC0 원본)  ──npm run assets──►  public/assets/gen/  ──Boot──►  Phaser 텍스처
                         재채색·덧그리기            manifest.json            물체 프레임·애니메이션 등록
```

- `npm run dev`, `npm run build` 전에 자동으로 돈다(predev / prebuild). 결과물은 git에 올리지 않는다.
- **캐릭터 추가**: 팩에서 바탕 캐릭터를 `assets-src/.../Actor/Characters/<이름>/`에 복사 → `content/characters/<id>.js`에 `sprite: { base, recolor, edits }`. 바꾸려는 색이 원본에 없으면 테스트가 실패한다(오타 방지).
- **물체 추가**: 팩 시트에서 사각형을 찾아 `content/art/pack.js`의 `OBJECTS`에 `rect`(그림)와 `foot`(충돌) 등록 → 맵에 `O('이름', x, y)`.
- **맵 수정 후**: `npm run validate`가 막힌 칸, **걸어서 닿을 수 없는 인물·물건·구역**까지 잡는다.

## 일러스트와 대화창 (`content/cg.js`, `src/ui/DialogBox.js`, `src/ui/CgLayer.js`)

- 진짜 일러스트가 있는 인물(`PORTRAITS`)은 대화창으로 말할 때 오른쪽 뒤에 상반신이 선다. 주인공·내레이션 차례에는 어둡게 남는다. 없는 인물은 대화창 안에 팩의 작은 도트 얼굴.
- 파일은 인물마다 폴더 하나: `public/assets/characters/<사는 곳>/<인물>/`(portrait = 기본, 그 밖은 표정). 코드로 그린 임시 일러스트는 쓰지 않는다.
- 이벤트 CG: `CG`에 파일, 또는 `bg`(배경 CG) + `figure`(인물). 생김새(색·테두리·글자)는 `src/ui/kit.js`.

## 게임 시계와 하루 일과 (`content/world/clock.js`, `src/field/systems/Clock.js`·`Schedules.js`)

- 시계가 도는 페이즈(`clock: true`)에서만 게임 시간이 흐른다. 게임 1분 = 현실 1초(하루 24분). 대화·컷신·수첩 중엔 멈춘다. 세이브의 `run.time { day, minute }`.
- 페이즈의 `day`(그날 날짜)와 `startAt`(시작 시각, 없으면 time에 따라 09:00/20:00)은 처음 들어설 때만 맞춘다.
- 조명은 시각을 따라 새벽·낮·노을·밤이 이어진다(`Lighting.setClock`). 시계 없는 이야기 장면(축제의 밤, 종탑의 밤)은 그 페이즈의 `time` 그대로.
- 하루 일과: 인물 파일의 `schedule`(시각 순서, `at`·`mode`·`say`·`task`·`home`·`when`). 시각이 바뀌면 길찾기(A*, `systems/Path.js`)로 걸어서 옮기고, `home`이면 맵 `objects`의 `residents`에 그 사람이 있는 건물 문으로 들어가 필드에서 사라진다. 페이즈가 직접 배치한 인물은 일과를 쓰지 않는다.
- 잠: 시계가 도는 날 밤(20시~4시)에 우리 집 잠자리에서 E → 다음 날 아침 6시, 같은 하루(또는 `phase.next`)를 새로 시작한다.
- 검증: 일과의 시각 형식, 장소, 걸을 수 있는 칸, 집 문 앞.

## 마을 습격 (`content/raids.js`, `src/field/systems/Raids.js`, `src/field/systems/FieldBattle.js`)

- 시계가 도는 날, 정해진 날·시각이 지나면 습격이 온다. `sign`은 장면만(8일 아침 털린 채소밭), `raid`는 경고 장면 → 무리가 북쪽 길에서 나타나 길찾기로 목표(곡식 더미·빵집)까지 걷는다.
- 오크와 부딪히거나 곁에서 E를 누르면 사이드뷰 전투(`FieldBattle`: 필드를 잠재우고 Battle을 띄웠다가 깨운다). 이기면 그 오크는 달아나고, 물러나면 그대로 간다. 다 쫓아내면 지킨 것, 하나라도 목표에 닿으면 못 지킨 것. 목표 줄은 "○○을(를) 지켜라". 함께 싸우는 사람: 나 + 지워지지 않은 셀레나·루.
- 날짜: 털린 밭(8일, 1장) · 정찰대(15일, 2장) · 토르크(24일, 3장, 예고를 읽어야 이긴다).
- 결과는 `raid.<id>.won/.lost/.over`와 `won`/`lost`의 플래그·호감도로 남는다(`granary.looted`, `bakery.burned`). 못 지킨 습격이 `FALL_AFTER`번 쌓이면 `village.fallen`.
- 오크·토르크는 팩의 Hunter를 초록 피부로 재채색하고 엄니(토르크는 부러진 엄니 + 붉은 망토)를 덧그렸다(`sprite.shareBase`).
- 아직 없는 것: 불탄 빵집·털린 곡식 더미의 그림. 브라우저 콘솔 `__ud.raid('scouts')`로 바로 불러 볼 수 있다.
- 검증: 시각 형식, 화자, 출발점·목표가 걸을 수 있는 칸인지.

## 퀘스트와 단서 수첩 (J)

- 퀘스트: `content/quests/`(막마다 파일), 돌리는 곳 `src/field/systems/Quests.js`. 받는 길은 주는 사람(`giver`)에게 말 걸기, `start.auto`(조건이 맞으면 저절로). 단계의 `done`: `{ flag }` `{ talk: 인물 }` `{ zone }` `{ when: 대본 조건 }`. 진행 중인 메인 퀘스트의 지금 단계가 왼쪽 위 할 일이 된다.
- 단서: `content/clues.js`의 `{ id, title, text, when }`. 조건이 맞는 순간 수첩에 적히고 알림이 뜬다(`src/field/systems/Clues.js`). 그때 알 수 있는 것만 쓴다.
- 수첩 창: `src/ui/NotebookPanel.js`. J(휴대폰은 J 버튼)로 열고, ←→ 쪽, ↑↓ 단서 고르기. 열려 있는 동안 주인공은 멈춘다.
- 퀘스트·단서는 걸으며 듣는 대사 중에도 따라잡는다.

## 저장과 확장성 (DB 대비)

```
게임 로직 ──► WorldMemory ──► SaveRepository ──► StorageAdapter
                                 (메모리 캐시)      ├─ LocalStorageAdapter (지금, 웹)
                                                   ├─ MemoryAdapter (테스트)
                                                   ├─ TauriFileAdapter (예정, 데스크톱: 게임 폴더에 세이브)
                                                   └─ RemoteAdapter (예정, 서버 DB)
```

- **어댑터 계약**은 비동기 `read / write / remove` 셋뿐이다(`core/storage/StorageAdapter.js`). 원격 DB로 바꿀 때 어댑터 하나만 새로 쓰고 `core/storage/index.js`에서 고른다.
- **Repository**는 시작할 때 한 번 읽어 메모리에 올리고, 이후 쓰기는 비동기로 흘려보낸다. 게임 루프가 네트워크를 기다리지 않는다.
- **세이브 스키마**는 버전이 있다(`core/save/SaveSchema.js`). 필드를 바꾸면 `VERSION`을 올리고 `MIGRATIONS`에 변환을 추가한다. 이 구조가 그대로 DB 테이블/문서의 기준이 된다.
  - `world`: 지워짐, 로드 횟수 — 세계의 기억
  - `run`: 장, 페이즈, 플래그, 호감도, 퀘스트(`quests`), 단서(`clues`), 게임 시계(`time`), 고향 페이즈(`home`) — 현재 진행. v6에서 퀘스트와 단서 수첩, v7에서 시계, v8에서 고향 페이즈가 붙었다
  - `meta`: 생성·수정 시각, `playerId`(계정 연동 자리)
- **공유 데이터**(서버 공통 붕괴, 정신체 도움, 도달률)는 `core/world/GlobalWorld.js` 한 곳으로만 나간다. 지금은 꺼져 있다.
- 조작 정책: 개인 데이터는 막지 않는다. 공유 데이터만 서버에서 상한 검증.

## 새 콘텐츠 추가하기

**인물**: `content/characters/<id>.js` 작성 → `index.js`에 등록. 새 머리·소품이 필요하면 `content/art/layers.js`에 레이어 추가. 미리보기로 확인.

**장**: `content/chapters/<장>/phases.js`, `script.js` 작성 → `chapters/index.js`에 등록. 이전 장 마지막 컷신의 `end.next`로 이어 준다.

**이벤트**: 해당 페이즈의 `events`에 한 줄 + `script.js`에 컷신 하나.

**맵**: `content/maps/village.js`의 `build()`에 사각형 배치. 장소(`spots`)와 구역(`zones`)에 이름을 붙이면 대본에서 이름으로 부른다.

추가한 뒤엔 항상 `npm run check` (검증 + 단위 테스트 + 빌드).

## 테스트

원칙: **"망가졌나?"는 기계가, "재밌나?"는 사람이** 확인한다. 기능을 넣을 때 테스트를 같이 넣는다.

| 층 | 무엇을 | 어디 | 명령 | 시간 |
| --- | --- | --- | --- | --- |
| 콘텐츠 검증 | 라벨 오타, 막힌 칸의 인물·물건, 지워진 사람이 말하는 대사, 켜지지 않는 플래그, 소프트락 | `tools/lib/validateContent.mjs` | `npm run validate` | 1초 |
| 단위 | 지워짐 규칙, 세이브 이관·저장 실패, 대본 조건, 이벤트 계기, 날짜 유틸, 에셋 빌드·재채색·종탑 변형, 물체 사각형, 맵 충돌, 자동 타일, 타이틀 장면 설정, 대사 깨짐·걷는 대사·빈자리, 전체 지도·길 맵 생성 | `tests/unit/` | `npm test` | 3초 |
| 논리 플레이스루 | **모든 지워짐 조합(16가지)**으로 봇이 프롤로그를 끝까지 플레이 | `tests/unit/content.test.js` | `npm test` | 포함 |
| E2E | 빌드한 실제 게임을 헤드리스 Chromium으로 완주 → CONTINUE → 가장 아낀 사람이 지워졌는지, RESET 후에도 안 돌아오는지 | `tests/e2e/` | `npm run test:e2e` | 2~3분 |

- **CI**: GitHub에 푸시하면 `.github/workflows/ci.yml`이 위 네 층을 자동으로 돌린다. 실패하면 리포 Actions 탭에서 원인과 스크린샷을 본다.
- E2E는 처음 한 번 `npx playwright install chromium`이 필요하다.
- E2E는 게임이 여는 `window.__game`, `window.__ud`로 상태를 읽고 플레이어를 순간이동시킨다(`tests/e2e/game.js`).
- 버그를 고치면 **그 버그를 재현하는 테스트를 먼저** 넣는다(예: `script-runner.test.js`의 aff+flag 회귀 테스트).
- 새 이벤트 계기(trigger)를 만들면 `event-director.test.js`에, 새 장을 만들면 `content.test.js`의 플레이스루에 추가한다.

## 개발 명령

```bash
npm run dev                              # 웹 개발 서버
npm run build                            # 웹 빌드 → dist/
npm run tauri dev                        # 데스크톱 창으로 실행 (Rust 필요)
npm run tauri build                      # EXE
npm run check                            # 검증 + 단위 테스트 + 빌드 (커밋 전에)
npm run validate                         # 콘텐츠 검증
npm test                                 # 단위 테스트 (npm run test:watch: 저장할 때마다)
npm run test:e2e                         # 실제 게임 자동 플레이
npm run assets                           # 에셋 빌드 (dev/build 전에 자동)
```

브라우저 콘솔: `await __ud.wipeAll()` 후 새로고침하면 세계까지 완전 초기화. `__game`은 Phaser 게임 객체.
